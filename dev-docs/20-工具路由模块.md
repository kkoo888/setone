### 20.3 核心服务

#### 20.3.1 ToolRegistry（tool-registry.ts）

工具注册表，使用 `Map<string, RegisteredTool>` 管理所有已注册工具。

**接口定义**：

```typescript
interface ToolDefinition {
  name: string
  description: string
  parameters?: Record<string, unknown>
  priority?: number
}

interface RegisteredTool {
  definition: ToolDefinition
  moduleId: string
  handler: (params: Record<string, unknown>) => Promise<unknown>
}
```

**方法**：

| 方法 | 说明 |
|------|------|
| `register(tool)` | 注册工具，同名工具按优先级覆盖 |
| `unregister(moduleId)` | 按模块 ID 注销该模块的所有工具 |
| `get(name)` | 按工具名获取已注册工具 |
| `getAll()` | 获取所有已注册工具 |
| `has(name)` | 检查工具是否已注册 |

**优先级覆盖机制**：
- 同名工具注册时，比较新旧工具的 `priority`（默认 0）
- 新工具优先级 <= 已有工具时，跳过注册并记录 warn 日志
- 新工具优先级 > 已有工具时，替换并记录 info 日志

#### 20.3.2 ToolRouter（tool-router.ts）

工具路由器，基于关键词匹配将用户意图路由到合适的工具。

**接口定义**：

```typescript
interface RouteResult {
  tool: RegisteredTool
  confidence: number
}
```

**构造参数**：

```typescript
constructor(
  logger: Logger,
  registry: ToolRegistry,
  settings?: { confidenceThreshold?: number }  // 默认 0.6
)
```

**方法**：

| 方法 | 说明 | 参数 | 返回值 |
|------|------|------|--------|
| `route(intent, context?)` | 根据意图路由到最匹配的工具 | 意图字符串 | `RouteResult \| null` |
| `listTools()` | 列出所有可用工具 | 无 | `Array<{ name, description, moduleId }>` |

**路由算法**：

```
1. 遍历所有已注册工具
2. 对每个工具计算匹配分数：
   - 工具名完全包含意图 或 意图完全包含工具名 → score = 1
   - 否则：将意图分词，统计在工具描述/名称中出现的词数比例 → score = matched/total
3. 过滤 score >= confidenceThreshold 的结果
4. 按 score 降序排列，返回最高分的工具
```

**置信度阈值**：默认 0.6，可通过模块配置覆盖。

#### 20.3.3 ToolExecutor（tool-executor.ts）

工具执行器，提供并发控制和统一的执行结果格式。

**接口定义**：

```typescript
interface ExecutionResult {
  success: boolean
  result?: unknown
  error?: string
  durationMs: number
}
```

**构造参数**：

```typescript
constructor(
  logger: Logger,
  settings?: { maxConcurrentExecutions?: number }  // 默认 5
)
```

**方法**：

| 方法 | 说明 | 参数 | 返回值 |
|------|------|------|--------|
| `execute(tool, params)` | 执行工具 | 工具实例 + 参数 | `Promise<ExecutionResult>` |
| `getRunningCount()` | 获取当前并发执行数 | 无 | `number` |

**并发控制**：
- 使用 `Map<string, Promise<ExecutionResult>>` 跟踪正在执行的任务
- 执行前检查 `running.size >= maxConcurrent`，达到上限时返回失败
- 执行完成后从 `running` Map 中移除
- 执行 ID 格式：`${toolName}-${startTime}`

**执行流程**：
```
1. 检查并发数是否超限
2. 记录开始时间，生成执行 ID
3. 调用 tool.handler(params)
4. 记录耗时，返回 ExecutionResult
5. 异常时返回 { success: false, error, durationMs }
```

### 20.4 模块入口（index.ts）

`ToolsModule` 实现 `Module` 接口，激活时创建三个核心服务并监听工具注册事件。

**提供的工具能力**：

| 工具名 | 说明 | 参数 | 返回值 |
|--------|------|------|--------|
| `tool_execute` | 执行工具 | `{ name: string, params?: Record<string, unknown> }` | `ExecutionResult` |
| `tool_list` | 列出所有工具 | 无 | `Array<{ name, description, moduleId }>` |
| `tool_route` | 根据意图路由工具 | `{ intent: string }` | `{ name: string, confidence: number } \| { name: null }` |

**事件监听**：
- `tool:register`：监听其他模块注册工具的事件，收到后调用 `registry.register(tool)`

**停用清理**：
- `deactivate()` 时移除 `tool:register` 事件监听

### 20.6 代码规范

- **注册表**：`Map<string, RegisteredTool>` 按工具名索引，支持优先级覆盖
- **路由器**：基于关键词匹配的简单路由算法（非 AI 路由）
- **执行器**：并发控制（默认 5），统一结果格式
- **事件驱动**：通过 `tool:register` 事件接收其他模块的工具注册
- **模块解耦**：工具注册通过事件总线，不直接依赖其他模块
