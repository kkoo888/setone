## 轮询注册中心重构 - 02:30 CST

### 问题分析
原 `PollingRegistry` 设计存在以下问题：
1. 核心轮询与模块轮询混在一起，没有区分
2. 模块 deactivate 后轮询任务不会自动清理（僵死任务）
3. 仪表盘每 5 秒轮询拉取整个列表，浪费 IPC
4. 渲染进程 helper 静默吞错，调试困难

### 重构方案
**核心思路：** 区分核心轮询和模块轮询，模块轮询绑定 moduleId，deactivate 自动清理，列表变更推送到渲染进程。

### 变更文件清单

| 文件 | 改动内容 |
|------|---------|
| `src/main/core/polling-registry.ts` | 新增 `registerForModule(task, moduleId)`、`unregisterByModule(moduleId)`、`notify()` 推送机制 |
| `src/main/core/module-loader.ts` | `deactivate()` finally 块新增 `pollingRegistry.unregisterByModule(moduleId)` |
| `src/main/ipc-handlers.ts` | 新增 `polling:registerModule` IPC 通道 |
| `src/renderer/src/utils/polling-helper.ts` | 新增 `registerModulePolling()`、`onPollingUpdate()` 监听推送 |
| `src/renderer/src/pages/SystemDashboardPage/index.tsx` | 轮询列表改为推送监听，去掉 `loadPollingTasks` 轮询 |

### 架构说明
- **核心轮询**（register）：性能监控、自动备份、状态栏等，不绑定模块，常驻
- **模块轮询**（registerForModule）：绑定 moduleId，模块关闭时自动清理
- **推送机制**：每次 register/unregister/tick/update 后，通过 `webContents.send('polling:updated')` 推送到所有窗口
- **仪表盘**：首次拉取一次列表，之后监听 `polling:updated` 事件更新

## 轮询详情弹窗 + 活动上报 - 02:45 CST

### 新增功能
点击仪表盘中任意轮询任务条目，弹窗展示该任务的完整运行详情。

### 弹窗内容
- 模块名 + 状态标签
- 描述、轮询间隔
- 累计执行次数（tickCount）
- 上次/下次执行时间
- 已运行时长
- 当前活动（lastActivity）
- 最近错误（lastError，红色高亮）
- 绑定模块 ID（如有）

### 活动上报机制
- `tick(id, activity?)` — 可选传入活动描述，自动累加 tickCount
- `update(id, { lastActivity?, lastError? })` — 模块执行中/出错时上报
- 数据由 Registry 内存维护，每次变更自动推送，零额外查询开销

| 文件 | 改动内容 |
|------|---------|
| `src/main/core/polling-registry.ts` | PollingTask 新增 tickCount/lastActivity/lastError；tick() 支持 activity 参数并自动累加 tickCount；update() 支持 lastActivity/lastError |
| `src/main/core/performance-monitor.ts` | tick 调用传入活动描述 "正在采集 CPU/内存/磁盘/GPU 数据" |
| `src/main/core/backup.ts` | runBackup 执行前后上报活动，出错时上报 lastError |
