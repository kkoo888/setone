### 变更1：修复打包后无法启动问题

- **问题现象**：打包后的 exe 双击运行提示"此应用无法在你的电脑上运行"
- **根因分析**：`electron-builder.yml` 中 `win.target` 设置为 `dir`（仅生成解压目录），不是完整的安装包格式
- **修复内容**：

#### electron-builder.yml
```yaml
# 修改前
win:
  target:
    - dir

# 修改后
win:
  target:
    - target: nsis
      arch:
        - x64
nsis:
  oneClick: false
  perMachine: false
  allowToChangeInstallationDirectory: true
  artifactName: ${productName}-Setup-${version}.${ext}
  shortcutName: 智能桌面助手
```

- 更新打包命令说明，推荐使用 NSIS 安装包方式

### 变更2：修复模块入口文件找不到问题

- **问题现象**：打包后运行提示 `模块入口文件不存在: index.js 或 index.ts`（模块 "tools" 激活失败）
- **根因分析**：
  1. 模块源码为 `.ts` 文件，打包后 Electron (Node.js) 无法直接执行 TypeScript
  2. 编译脚本 `build-modules.mjs` 会将模块编译为 JS 到 `modules-dist/`，但未在打包流程中调用
  3. `electron-builder.yml` 的 `files` 只包含 `modules/`，未包含 `modules-dist/`
  4. `getModulesPath()` 打包模式下只指向 `modules/`，未检查编译产物

- **修复内容**：

#### electron-builder.yml
```yaml
# 新增 modules-dist 到打包文件列表
files:
  - dist/**/*
  - modules/**/*
  - modules-dist/**/*    # ← 新增
```

#### src/main/index.ts
```typescript
// 打包模式下优先使用编译后的 modules-dist
const packagedCompiled = join(app.getAppPath(), 'modules-dist')
if (existsSync(packagedCompiled)) {
  return packagedCompiled
}
return packagedSource
```

#### package.json
```json
// prebuild 现在会先编译模块再清理
"prebuild": "node scripts/clean.js && node scripts/build-modules.mjs"
```

#### BUILD_GUIDE.md
- 更新构建步骤说明，包含模块编译流程

- **状态**：✅ 已修复，待本地重新打包验证

### 变更3：新增工作流自动化模块（workflow）

- **类型**：新模块开发
- **模块目录**：`desktop/modules/workflow/`
- **功能概述**：可视化工作流编排，支持触发器 + 多步骤自动化执行

#### 文件清单
| 文件 | 说明 |
|------|------|
| `module.json` | 模块配置：6个工具、3个事件消费、资源限制 |
| `index.ts` | 主模块类，实现 Module 接口，8个 Capability |
| `types.ts` | 完整类型定义 + 3个内置模板（日报/备份/代码审查） |
| `services/CronParser.ts` | Cron 表达式解析器（支持 `*`、`0/n`、范围、列表） |
| `services/StepExecutor.ts` | 步骤执行器：模板替换、条件判断、重试、超时 |
| `services/WorkflowEngine.ts` | 执行引擎：顺序编排、暂停、全局超时控制 |
| `services/WorkflowScheduler.ts` | 调度器：cron 定时 / 事件监听 / 快捷键触发 |
| `services/WorkflowStore.ts` | SQLite 持久化（workflows + workflow_runs 表） |

#### 提供的工具
- `workflow_create` — 创建工作流
- `workflow_execute` — 执行工作流
- `workflow_list` — 列出工作流
- `workflow_delete` — 删除工作流
- `workflow_pause` — 暂停执行中的工作流
- `workflow_log` — 获取执行日志
- `workflow_templates` — 获取内置模板列表
- `workflow_create_from_template` — 从模板创建工作流

#### 技术要点
- 步骤间传参：`{{step1.output}}` 模板语法，支持递归解析
- 条件判断：`eq` / `ne` / `contains` / `gt` / `lt` 运算符
- 错误处理：`stop`（终止）/ `skip`（跳过）/ `retry`（重试，递增间隔）
- 超时控制：单步骤 30s，全局 5 分钟（可配置）
- 数据库：自动创建 `workflows` 和 `workflow_runs` 表

- **状态**：✅ 已完成，编译通过，已合并到 main

### 变更4：修复 CronParser JSDoc 注释问题

### 变更6：修复 clean.js 打包时 dist-packaged 权限问题

- **问题现象**：`npm run build` 时报 `EPERM, Permission denied: dist-packaged`
- **根因分析**：
  1. `dist-packaged` 是 electron-builder 打包输出目录，打包过程中会被 Electron 进程锁定
  2. `clean.js` 在 prebuild 阶段尝试删除该目录，但 Windows 上目录被锁定导致 EPERM
  3. 该目录不应在每次 build 时清理，只在需要重新打包时手动清理
- **修复内容**：

#### scripts/clean.js
```js
// 修改前
const dirs = ['dist', 'dist-packaged', 'modules-dist']

// 修改后
const dirs = ['dist', 'modules-dist']
// dist-packaged 不再自动清理（Windows 上会被 Electron 锁定）
// 错误处理改为捕获所有异常，不再只匹配 EPERM/EBUSY
```

- **教训记录**：
  - ⚠️ **Windows 上不要在 prebuild 中清理 dist-packaged**，该目录会被 Electron 进程锁定
  - ⚠️ clean.js 的错误处理要捕获所有异常，不能只匹配特定错误码
  - ✅ dist-packaged 需要手动清理时，先关闭 Electron 再删除

- **状态**：✅ 已修复
