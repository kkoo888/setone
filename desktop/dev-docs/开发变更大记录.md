## 2026-05-21 Live2D5 模块路径修复与功能分析

### Core SDK 和 Shader 路径修复
- 问题：打包后 file:// 协议下绝对路径 `/lib/...` 解析到磁盘根目录
- 修复：改为 `./` 相对路径，DOM API 相对 HTML 文档解析
- cubism5-service.ts: `'./lib/live2dcubismcore5.min.js'`
- cubismshader_webgl.ts: `'./Framework/Shaders/WebGL/'`
- Live2D5PetPage.tsx: `new URL('./live2d/Hiyori/...', document.baseURI).href`

### waitForShaders 修复
- 问题：`this.renderer.waitForShaders is not a function`
- 原因：Cubism SDK 没有 waitForShaders 方法
- 修复：在 initRenderer() 中调用 renderer.loadShaders()，移除 waitForShaders 调用

### Demo vs 模块功能差异分析
缺失效果清单：
| 效果 | Demo 实现 | 模块状态 |
|------|----------|---------|
| 物理演算 | CubismPhysicsUpdater | ❌ 缺失 |
| 自动眨眼 | CubismEyeBlinkUpdater | ❌ 缺失 |
| 呼吸效果 | CubismBreathUpdater | ❌ 缺失 |
| 鼠标注视 | CubismLookUpdater | ❌ 缺失 |
| 口型同步 | CubismLipSyncUpdater | ❌ 缺失 |
| Pose 切换 | CubismPoseUpdater | ❌ 缺失 |
| 点击交互 | hitTest + 随机表情/动作 | ❌ 缺失 |
| 拖拽交互 | setDragging | ❌ 缺失 |
| UpdateScheduler | 统一管理所有 Updater | ❌ 缺失 |

### Cubism SDK 版本选型结论
- 选择 Cubism SDK for Web（TypeScript + WebGL）
- 与 Electron + React + Vite 技术栈完全匹配
- Native SDK 开发成本高 5 倍，且最终还是走 WebGL 渲染

### 背景
对比 Demo（LAppModel）与项目模块（cubism5-service）的实现差异，发现旧版手动使用底层 API 拼装模型，缺少大量效果：
- 物理演算、自动眨眼、呼吸、鼠标注视、Pose、LipSync、UpdateScheduler

### 决策
用户决定：删除旧代码，基于 CubismUserModel 重新开发，保持代码整洁。

### 实施
1. **新建 AppModel**（`modules/live2d-5/services/AppModel.ts`）
   - 继承 `CubismUserModel`，使用 SDK 标准加载链路
   - 使用 `CubismModelSettingJson` 解析 model3.json
   - 通过 `CubismUpdateScheduler` 统一调度所有 Updater
   - 预加载所有表情和动作到缓存

2. **重写 cubism5-service.ts**
   - 用 `AppModel` 替代手动拼装
   - 对外接口不变（loadModel/setExpression/playMotion/destroy）
   - Live2D5PetPage 无需改动

3. **新增效果**
   - CubismEyeBlinkUpdater — 自动眨眼

   - CubismLookUpdater — 鼠标注视
   - CubismPhysicsUpdater — 物理演算
