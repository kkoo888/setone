## 四、新增模块完整 Checklist

### 4.1 后端（modules/）

- [ ] **module.json** — 填写完整的元数据，特别是 `provides` 声明所有工具
- [ ] **index.ts** — 实现 `Module` 接口的三个方法：`activate`、`deactivate`、`getCapabilities`
- [ ] **types.ts** — 定义模块使用的类型接口
- [ ] **services/** — 业务逻辑从 index.ts 拆分到 services 目录
- [ ] **deactivate()** — 必须清理所有资源（见第五节）
- [ ] **getCapabilities()** — 返回所有工具能力，每个工具必须有 `name`、`description`、`handler`

### 4.2 IPC 注册（自动）

模块的工具会**自动注册为 IPC 处理器**，无需手动操作：

```
模块 activate → getCapabilities() 返回工具列表
                → ipc-handlers.ts 的 registerModuleCapabilities() 自动注册
                → 前端可通过 window.electronAPI.invoke('工具名') 调用
```

**工具名即 IPC 通道名**，直接用 `invoke('kb_list')` 调用，不需要加模块前缀。

### 4.3 前端（src/renderer/）

#### 4.3.1 侧边栏入口

在 `Sidebar.tsx` 的 `MODULE_PANELS` 数组中添加：

```typescript
  // ...

```

## 五、deactivate() 资源清理规范 ⚠️

**这是最容易遗漏的部分！** 每个模块停用时必须清理所有资源，否则会造成内存泄露和功能异常。

### 5.1 必须清理的资源类型

| 资源类型 | 清理方式 | 示例 |
|---------|---------|------|
| **eventBus 监听** | `context.eventBus.off(event, handler)` | 取消所有 `.on()` 注册 |
| **定时器** | `clearTimeout(timer)` / `clearInterval(id)` | 清理所有 setTimeout/setInterval |
| **数据库引用** | `this.db = undefined as never` | 断开 DB 引用 |
| **文件监听** | `watcher.unwatchAll()` | 停止所有文件监听 |
| **外部进程** | `process.kill()` / `child.kill()` | 终止子进程 |
| **Electron 资源** | `tray.destroy()` / `globalShortcut.unregisterAll()` | 清理原生资源 |

### 5.2 eventBus 监听清理模板

```typescript
export default class XxxModule implements Module {
  private context!: ModuleContext
  private eventHandler?: (data: unknown) => void  // ⚠️ 保存引用

  async activate(context: ModuleContext): Promise<void> {
    this.context = context
    
    // ⚠️ 保存 handler 引用，以便 deactivate 时取消
    this.eventHandler = (data: unknown) => {
      // 处理逻辑
    }
    context.eventBus.on('some:event', this.eventHandler)
  }

  async deactivate(): Promise<void> {
    // ⚠️ 取消 eventBus 监听
    if (this.eventHandler) {
      this.context.eventBus.off('some:event', this.eventHandler)
      this.eventHandler = undefined
    }
    this.context.logger.info('XXX模块已停用')
  }
}
```

### 5.3 定时器清理模板

```typescript
export default class XxxModule implements Module {
  private timers = new Map<string, NodeJS.Timeout>()

  async deactivate(): Promise<void> {
    // ⚠️ 清理所有定时器
    for (const timer of this.timers.values()) {
      clearTimeout(timer)
    }
    this.timers.clear()
  }
}
```

### 5.4 完整 deactivate 检查清单

在编写 `deactivate()` 时，逐项检查：

- [ ] 所有 `eventBus.on()` 是否有对应的 `eventBus.off()`？
- [ ] 所有 `setTimeout` / `setInterval` 是否已 `clearTimeout` / `clearInterval`？
- [ ] 所有 `db` 引用是否已清理？
- [ ] 所有文件监听是否已停止？
- [ ] 所有外部进程是否已终止？
- [ ] 所有 Electron 原生资源是否已销毁？

## 六、热插拔机制

### 6.1 模块生命周期

```
discovered → loading → active ⇄ disabled
                          ↓
                        error → (retry / disabled)
```

### 6.2 禁用模块的完整链路

用户在 ModulesPage 点击关闭开关时：

```
前端 toggleModule(id)
  → 调用 IPC 'module:disable'
  → moduleManager.disableModule(id)
  → config 保存禁用状态
  → loader.deactivate(id)
  → 模块实例.deactivate()  ← 你的清理代码在这里
  → reg.instance = null
  → eventBus.emit('on_module_unloaded', { moduleId })
  → unregisterModuleCapabilities(moduleId)  ← 自动注销 IPC
  → 前端侧边栏隐藏入口  ← Sidebar 自动响应
  → 如果当前在该模块页面，自动跳转到对话页
```

### 6.3 启用模块的完整链路

```
前端 toggleModule(id)
  → 调用 IPC 'module:enable'
  → moduleManager.enableModule(id)
  → config 移除禁用状态
  → loader.activate(id)
  → 模块实例.activate(context)
  → eventBus.emit('on_module_unloaded', { moduleId })  ← 注销旧 IPC
  → registerModuleCapabilities()  ← 重新注册 IPC
  → 前端侧边栏显示入口
```

## 七、常见错误与解决

### 7.1 `No handler registered for 'xxx'`

**原因**：模块的工具没有注册为 IPC 处理器  
**解决**：确保 `module.json` 的 `provides` 中声明了该工具，且 `getCapabilities()` 返回了对应的 handler

### 7.2 禁用模块后功能仍然可用

**原因**：deactivate 未清理资源，或 IPC 处理器未注销  
**解决**：按第五节规范编写 deactivate()

### 7.3 重新启用模块后功能异常

**原因**：上次 deactivate 清理不彻底，残留了旧状态  
**解决**：activate 中重新初始化所有资源，不要依赖上次的实例状态

### 7.4 `undefined\SKILL.md` 路径错误

**原因**：`skill_list` 返回数据缺少 `path` 字段  
**解决**：确保 `getCapabilities()` 返回的数据包含所有前端需要的字段

## 八、工具参数 Schema 规范 ⚠️

**这是让 LLM 正确调用工具的关键！** 如果工具没有参数定义，LLM 不知道该传什么参数，会乱传或直接不调用。

### 8.1 问题背景

`ipc-handlers.ts` 中的 `collectModuleTools()` 会将模块工具注册给 LLM 使用。参数来源有三级回退：

```
模块自定义参数(cap.parameters) → 静态映射表(TOOL_PARAM_SCHEMAS) → 空 schema
```

如果三级都为空，LLM 看到的工具参数是 `{ properties: {} }`，完全不知道需要什么参数。

### 8.2 新增模块必须做

在 `getCapabilities()` 返回的每个 tool 类型能力中，**必须**通过以下方式之一提供参数定义：

#### 方式一：在 Capability 中直接定义（推荐）

```typescript
getCapabilities(): Capability[] {
  return [
    {
      type: 'tool',
      name: 'xxx_action',
      description: '执行XXX操作',
      priority: 10,
      moduleId: this.id,
      // ✅ 直接定义参数 schema
      parameters: {
        type: 'object',
        properties: {
          target: { type: 'string', description: '操作目标' },
          count: { type: 'number', description: '数量', default: 1 }
        },
        required: ['target']
      },
      handler: {
        execute: async (p) => {
          const { target, count } = p as { target: string; count?: number }
          // ...
        }
      }
    }
  ]
}
```

#### 方式二：在 tool-param-schemas.ts 中添加映射

如果不想在模块代码中写 schema，可以在 `src/main/core/tool-param-schemas.ts` 的 `TOOL_PARAM_SCHEMAS` 对象中添加：

```typescript
xxx_action: {
  type: 'object',
  properties: {
    target: { type: 'string', description: '操作目标' },
    count: { type: 'number', description: '数量', default: 1 }
  },
  required: ['target']
},
```

### 8.3 参数 Schema 编写规范

| 字段 | 说明 | 示例 |
|------|------|------|
| `type` | 参数类型 | `'string'` / `'number'` / `'boolean'` / `'array'` / `'object'` |
| `description` | 参数用途描述（LLM 靠这个理解参数含义） | `'要读取的文件路径'` |
| `required` | 必填参数列表 | `['path', 'content']` |
| `enum` | 可选值枚举 | `['left', 'right', 'middle']` |
| `default` | 默认值 | `1` / `'left'` |
| `items` | 数组元素类型（type=array 时） | `{ type: 'string' }` |

### 8.4 检查清单

新增或修改模块工具后，逐项检查：

- [ ] 每个 tool 类型能力都有参数定义（方式一或方式二）
- [ ] `description` 清晰描述参数用途（LLM 靠这个理解）
- [ ] 必填参数列在 `required` 中
- [ ] 有可选值的参数加了 `enum`
- [ ] 参数名与 handler 中解构的变量名一致

## 九、测试验证

每次开发/修改模块后，必须验证：

1. **启动测试** — 应用启动，模块正常激活，无报错
2. **功能测试** — 通过 AI 对话调用模块工具，返回正确结果
3. **禁用测试** — 在 ModulesPage 关闭模块：
   - 侧边栏入口消失
   - AI 无法调用该模块工具（报错"已禁用"）
   - 控制台无资源泄露警告
4. **重新启用测试** — 重新打开模块：
   - 侧边栏入口出现
   - 功能恢复正常
5. **热重载测试** — `module:reload` 后功能正常
6. **工具调用测试** — AI 对话中调用工具，确认参数传递正确（见第八节）

## 十一、前端 UI/CSS 样式规范 ⚠️

**模块页面必须有独立的 CSS 样式文件，不能只写 class 不写样式！**

### 11.1 样式文件结构

每个模块页面的样式存放在：

```
src/renderer/src/styles/pages/<module-name>.css
```

然后在 `src/renderer/src/styles/global.css` 中导入：

```css
@import './pages/<module-name>.css';
```

### 11.2 设计体系（必须遵循）

所有模块页面必须使用项目的 CSS 变量体系，**禁止硬编码颜色值**：

```css
/* ✅ 正确 — 使用变量 */
.my-card {
  background: var(--color-bg-primary);
  border: 1px solid var(--color-border);
  color: var(--color-text-primary);
  border-radius: var(--radius-lg);
  padding: var(--spacing-md);
  font-size: var(--font-size-sm);
  transition: all var(--transition-fast);
}

/* ❌ 错误 — 硬编码 */
.my-card {
  background: #fff;
  border: 1px solid #e0e0e0;
  color: #333;
  border-radius: 12px;
  padding: 16px;
}
```

#### 变量速查表

| 类别 | 变量 | 用途 |
|------|------|------|
| **背景** | `--color-bg-primary` | 主背景 |
| | `--color-bg-secondary` | 次背景（卡片、侧边栏） |
| | `--color-bg-tertiary` | 三级背景（hover、active） |
| **文字** | `--color-text-primary` | 主文字 |
| | `--color-text-secondary` | 次文字 |
| | `--color-text-tertiary` | 辅助文字（时间戳、标签） |
| **强调色** | `--color-accent` | 主强调色（蓝紫色） |
| | `--color-accent-hover` | hover 状态 |
| | `--color-success` | 成功（绿） |
| | `--color-warning` | 警告（黄） |
| | `--color-error` | 错误（红） |
| **边框** | `--color-border` | 默认边框 |
| **间距** | `--spacing-xs/sm/md/lg/xl` | 4/8/16/24/32px |
| **圆角** | `--radius-sm/md/lg/full` | 4/8/12/9999px |
| **字体** | `--font-size-xs/sm/md/lg/xl` | 12/14/16/18/24px |
| | `--font-family` | 主字体 |
| | `--font-mono` | 等宽字体（代码） |
| **动画** | `--transition-fast/normal/slow` | 150/250/350ms ease |

### 11.3 暗色主题适配（必须）

每个页面**必须**适配暗色主题。使用 `[data-theme='dark']` 选择器：

```css
/* 亮色（默认） */
.my-card {
  background: var(--color-bg-primary);
  border: 1px solid var(--color-border);
}

/* 暗色适配 */
[data-theme='dark'] .my-card {
  border-color: rgba(255, 255, 255, 0.06);
```

## 十二、前后端对齐规范（踩坑记录）⚠️

**以下问题曾导致多个模块"有界面但功能不生效"，务必避免！**

### 12.1 类型文件必须存在

前端页面如果 import 了类型文件，该文件**必须存在**，否则编译直接报错。

```
❌ src/renderer/src/types/knowledge-base.ts  ← 不存在，编译失败
✅ src/renderer/src/types/knowledge-base.ts  ← 必须创建
```

**规则**：如果页面写了 `import { XXX } from '../types/xxx'`，必须确保 `src/renderer/src/types/xxx.ts` 存在且导出了所有用到的类型。

### 12.2 IPC 通道名必须一致

前端 `invoke('工具名')` 的工具名必须与后端注册的**完全一致**。

```typescript
// ❌ 前端调用
await window.electronAPI.invoke('module_list')     // 下划线
// ✅ 后端注册
ipcMain.handle('module:list', ...)                  // 冒号

// ❌ 前端调用
await window.electronAPI.invoke('workflow_create_from_template')  // 不存在
// ✅ 后端实际有
workflow_create                                        // 用这个代替
```

**规则**：修改前端 invoke 调用前，先在 `ipc-handlers.ts` 和 `modules/*/module.json` 中确认工具名存在。

### 12.3 返回格式要兼容

不同 IPC handler 的返回格式可能不同：

```typescript
// 格式 A：模块工具（通过 getCapabilities 注册）
{ success: true, data: [...] }

// 格式 B：直接注册的 IPC（ipcMain.handle）
// 直接返回数据，不包装 success
[...]

// 前端必须兼容两种格式：
const res = await window.electronAPI.invoke('xxx')
if (Array.isArray(res)) setData(res)           // 格式 B
else if (res?.success) setData(res.data ?? [])  // 格式 A
```

### 12.4 模块工具 vs IPC 直接注册

| 注册方式 | 位置 | 自动 IPC | 返回格式 |
|---------|------|---------|---------|
| `getCapabilities()` → tool | `modules/*/index.ts` | ✅ 自动注册 | `{ success, data }` |
| `ipcMain.handle()` | `src/main/ipc-handlers.ts` | ❌ 手动注册 | 直接返回 |

### 12.5 前后端对齐检查清单

新增或修改模块功能后，逐项检查：

- [ ] 前端 `invoke('xxx')` 的工具名在后端存在
- [ ] 前端 import 的类型文件存在
- [ ] 前端处理了后端返回的数据格式
- [ ] `module.json` 的 `provides` 声明了所有工具
- [ ] `getCapabilities()` 返回了所有声明的工具
- [ ] 工具参数 schema 已定义（见第八节）

### 12.6 `provides`/`consumes` 未定义导致激活崩溃

**错误信息**：`Cannot read properties of undefined (reading 'filter')` in `createScopedEventBus`

**根因**：`module.json` 中没有声明 `provides` 或 `consumes` 字段时，传入 `createScopedEventBus()` 的值为 `undefined`，调用 `.filter()` 直接崩溃。

**已修复**：`scoped-event-bus.ts` 参数改为可选 + 空值合并 `?? []`；`module-loader.ts` 调用处加 `?? []`。

**开发规范**：
- `module.json` 中即使没有 `provides`/`consumes`，也要写空数组 `[]`
- 后端代码中对 `provides`/`consumes` 的使用必须加 `?? []` 空值保护
- 新增模块必须在 `module.json` 中声明 `provides` 和 `consumes`（可为空数组）
