# 本地文件路径加载全局扫描报告

> 扫描时间：2026-05-22  
> 范围：`setone/desktop` 项目全量源码（排除 node_modules、lib/SDK、tests）

## 扫描目标

找出所有涉及本地文件路径加载的位置，重点关注：

1. renderer 进程中使用 `fetch()` 加载本地文件（非 HTTP API）
2. 使用 `file://` 或路径拼接加载资源
3. 使用 `readFileSync` / `readFile` 读取文件后传给 renderer
4. 涉及模型、贴图、音频、配置文件等本地资源加载

## 一、modules/live2d-5/ — 核心重灾区

### 1.1 `services/AppModel.ts` — Cubism 5 模型加载（renderer 进程 fetch 本地文件）

| 行号 | 资源类型 | 路径构造方式 | 受自定义协议影响 |
|------|----------|-------------|-----------------|
| 149 | model3.json | `this._modelPath`（来自参数，由上层拼接） | ✅ 是 |
| 270 | .moc3 模型文件 | `this._modelDir + mocFile`（字符串拼接） | ✅ 是 |
| 377 | physics.json | `this._modelDir + physicsFile` | ✅ 是 |
| 392 | pose.json | `this._modelDir + poseFile` | ✅ 是 |
| 412 | userdata.json | `this._modelDir + userDataFile` | ✅ 是 |
| 577 | expression 文件 | `this._modelDir + file`（循环加载所有表情） | ✅ 是 |
| 613 | motion 文件 | `this._modelDir + file`（循环加载所有动作） | ✅ 是 |
| 310 | 纹理图片 (.png) | `this._modelDir + texFile`，通过 `new Image()` + `img.src = url` 加载 | ✅ 是 |

**路径构造逻辑**：`model3Path` 参数传入后，截取目录部分 `this._modelDir = model3Path.substring(0, model3Path.lastIndexOf('/') + 1)`，然后与文件名字符串拼接。所有资源通过 `fetch()` 在 renderer 进程加载。

**关键风险**：如果 `model3Path` 使用 `file://` 协议，拼接后的路径在 Electron renderer 中默认会被 `webSecurity` 拦截。如果使用 `local-file://` 自定义协议，所有 fetch 调用都会失败。

| 170 | .wav 音频文件 | `filePath` 参数直接传入 | ✅ 是 |

`loadWavFile(filePath)` 使用 `fetch(filePath)` 加载 WAV 音频用于唇形同步。

### 1.4 `ui/Live2D5PetPage.tsx` — 独立宠物窗口 renderer

| 行号 | 操作 | 路径构造方式 | 受自定义协议影响 |
|------|------|-------------|-----------------|
| 30-39 | 解析模型路径 | 相对路径用 `new URL(modelPath, document.baseURI).href`，绝对路径直接用 | ✅ 是 |

`modelPath` 来自 IPC 调用 `live2d5_get_applied_model`，返回值形如 `./live2d/Hiyori/Hiyori.model3.json`。通过 `document.baseURI` 解析为完整 URL 后传给 `cubism5Service.loadModel()`，最终进入 `AppModel.loadAssets()` 的 fetch 链。

## 总结

### 高度风险（renderer 进程 fetch 本地文件）

| 序号 | 文件 | 行号 | 说明 |
|------|------|------|------|
| 1 | `modules/live2d-5/services/AppModel.ts` | 149, 270, 377, 392, 412, 577, 613 | 8 处 `fetch()` 加载本地模型/纹理/音频，全部字符串拼接 |
| 2 | `modules/live2d-5/services/AppModel.ts` | 310 | `new Image()` + `img.src = url` 加载纹理图片 |
| 3 | `modules/live2d-5/services/WavFileHandler.ts` | 170 | `fetch()` 加载 WAV 音频 |
| 4 | `src/renderer/src/pages/QuickPreviewPage/index.tsx` | 71 | 直接 `file://` 拼接 `<img src>` |
| 5 | `src/renderer/src/components/live2d/Live2DCanvas.tsx` | 19 | `new URL('/live2d/...', import.meta.url)` |
| 6 | `src/renderer/src/pages/Live2D5PetPage.tsx` | 71 | `new URL('./live2d/...', window.location.href)` |
| 7 | `modules/live2d-5/ui/Live2D5PetPage.tsx` | 39 | `new URL(modelPath, document.baseURI)` |

### 不受影响（主进程 fs 操作）

所有 `src/main/core/` 和 `modules/` 下主进程侧的 `readFileSync` / `readFile` 均使用 Node.js fs 模块直接读取，不受自定义协议影响。

### 不受影响（远程 HTTP）

- `src/main/core/ai-service.ts` — Ollama API
- `modules/skill/SkillInstaller.ts` — 远程下载
- `modules/knowledge-base/services/DatasetCatalog.ts` / `DatasetDownloader.ts` — GitHub 远程
- `modules/proactive/services/weather-service.ts` — 天气 API
- `modules/vision/`, `modules/screen/`, `modules/memory/` — Ollama API
