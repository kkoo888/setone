# 常见问题与解决方案

> 记录开发过程中遇到的问题和解决方案，避免重复踩坑

---

## 1. 构建相关

### 1.1 clean.js EPERM 错误（dist-packaged）

- **日期**：2026-05-17
- **现象**：`npm run build` 报 `EPERM, Permission denied: dist-packaged`
- **原因**：Windows 上 Electron 进程会锁定 `dist-packaged` 目录，prebuild 阶段无法删除
- **解决**：从 clean.js 的清理列表中移除 `dist-packaged`，只清理 `dist` 和 `modules-dist`
- **预防**：❌ 不要在 prebuild 中自动清理 dist-packaged

### 1.2 模块加载失败（path 未存储）

- **日期**：2026-05-17
- **现象**：所有模块 `module:enable` 返回 false，模块管理页面全部加载失败
- **原因**：`ModuleRegistration` 类型缺少 `path` 字段，`register()` 收到路径但没存储，`activate()` 读到的路径是 undefined
- **解决**：`ModuleRegistration` 加 `path` 字段，`register()` 存储路径
- **预防**：⚠️ 注册时必须存储模块路径，激活时才能找到入口文件

### 1.3 modules-dist 不存在导致模块无法加载

- **日期**：2026-05-17
- **现象**：模块加载报错，Node.js 无法直接 import .ts 文件
- **原因**：`modules-dist` 目录不存在（未编译），回退到源码 .ts 文件但 Node.js 不支持
- **解决**：运行 `node scripts/build-modules.mjs` 编译模块
- **预防**：⚠️ 每次修改模块代码后都要重新编译

### 1.4 ModuleRuntimeConfig 运行时值未注入

- **日期**：2026-05-17
- **现象**：技能扫描不到本地 skills，skillSearchPaths 是 undefined
- **原因**：`ModuleLoader.createContext()` 把 ConfigManager 强制转型为 ModuleRuntimeConfig，但 skillSearchPaths 等运行时值从未注入
- **解决**：在 createContext 中用 Object.assign 组合运行时值
- **预防**：⚠️ ModuleRuntimeConfig = ModuleRuntimeValues + ConfigManager，两者都要有

## 2. Live2D 相关

### 2.1 Cubism Framework 初始化失败

- **日期**：2026-05-17
- **现象**：`Failed to start up Cubism 4 framework. Cannot read properties of undefined (reading 'initializeAmountOfMemory')`
- **原因**：pixi-live2d-display 导入时找不到全局 PIXI，导致 Cubism Framework 初始化失败
- **解决**：先 `import('pixi.js')` 并暴露到 `window.PIXI`，再 `import('pixi-live2d-display/cubism4')`
- **预防**：⚠️ 必须先暴露 PIXI 到全局再导入 pixi-live2d-display

### 2.2 Canvas 挂载失败（pixi.js v7 vs v8）

- **日期**：2026-05-17
- **现象**：容器或 canvas 不存在，跳过挂载
- **原因**：pixi.js v7 的 canvas 属性是 `app.view`，v8 是 `app.canvas`，代码只检查了 `app.canvas`
- **解决**：兼容两个版本 `(app.canvas ?? app.view)`
- **预防**：⚠️ pixi.js v7 用 app.view，v8 用 app.canvas

### 2.3 容器尺寸为 0 时 canvas 初始化失败

- **日期**：2026-05-17
- **现象**：容器尺寸 0x0，PIXI Application 创建为 0x0
- **原因**：canvas 初始化太早，DOM 还没渲染出容器尺寸
- **解决**：加入等待容器尺寸的逻辑（最多等 3 秒）
- **预防**：⚠️ canvas 初始化前要确保容器有有效尺寸

### 2.4 Fallback 组件覆盖整个页面

- **日期**：2026-05-17
- **现象**：Live2D 加载失败后页面变成空白，只有错误提示
- **原因**：Live2DProvider 的 fallback 接管了整个页面
- **解决**：Live2DPage 不直接使用 Live2DCanvas，改为状态卡片显示
- **预防**：⚠️ 不要在页面级别使用会触发全局 fallback 的组件

## 3. 导入路径相关

### 3.1 ModulesPage 导入路径多了一层

- **日期**：2026-05-17
- **现象**：`Could not resolve "../../stores/useModulesStore"`
- **原因**：ModulesPage.tsx 在 pages/ 目录下，导入 stores 只需要 `../stores/`，代码写了 `../../stores/`
- **解决**：改为 `../stores/useModulesStore`
- **预防**：⚠️ 注意文件层级，pages/ 下的文件到 stores/ 只需上一层

### 3.2 组件导入路径缺少子目录

- **日期**：2026-05-17
- **现象**：`Could not resolve "./components/ModuleCard"`
- **原因**：ModulesPage.tsx 在 pages/ 下，组件在 pages/ModulesPage/components/ 下，路径少了 ModulesPage/
- **解决**：改为 `./ModulesPage/components/ModuleCard`
- **预防**：⚠️ 注意组件是否在子目录中

## 4. Git 相关

### 4.1 Git push 网络超时

- **日期**：2026-05-17
- **现象**：`GnuTLS recv error (-110): The TLS connection was non-properly terminated`
- **原因**：网络不稳定或 GitHub 连接超时
- **解决**：重试即可，设置较长超时时间
- **预防**：⚠️ push 时设置 60s 以上超时
