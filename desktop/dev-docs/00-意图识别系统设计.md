# 意图识别系统设计

> 版本：v1.0 | 作者：小茜 | 日期：2026-05-19
> 状态：设计阶段

---

## 1. 背景与目标

### 1.1 背景

本项目是一个本地桌面 Agent 应用（Electron），硬件环境为：

- **CPU**：AMD 3800（8核16线程）
- **GPU**：无（纯 CPU 推理）
- **内存**：30GB

在此约束下，需要合理利用多个本地大模型来实现 Agent 的核心功能，同时保证用户体验流畅。

### 1.2 目标

设计一套**轻量级意图识别系统**，实现：

1. 用户输入自动识别意图，路由到对应功能模块
2. 支持边用边学，越用越精准
3. CPU 环境下延迟 < 50ms，用户无感
4. 不依赖云端服务，完全本地运行

---

## 2. 方案对比分析

| 方案 | 速度 | 准确度 | 学习能力 | CPU 适合度 | 内存占用 |
|------|------|--------|---------|-----------|---------|
| 纯规则匹配 | ⚡ 瞬间 | 低（覆盖不全） | ❌ 不支持 | ✅ 零成本 | 0 |
| 小模型推理（3B LLM） | 🐢 2-5秒 | 中高 | ⚠️ 需微调（CPU 不现实） | ❌ 太慢 | ~3GB |
| **嵌入向量匹配** | **⚡ ~20ms** | **中高** | **✅ 天然支持** | **✅ 最佳** | **~0.5GB** |

**结论：采用嵌入向量匹配方案**，利用已有的 `nomic-embed-text` 嵌入模型（274MB）做意图分类。

## 4. 核心数据结构

### 4.1 意图条目

```typescript
interface IntentEntry {
  /** 意图标识（模块名） */
  intent: string
  /** 意图描述（可读） */
  description: string
  /** 用户触发示例语句 */
  examples: string[]
  /** 示例语句的平均嵌入向量 */
  vector: number[]
  /** 累计命中次数（用于权重排序） */
  hitCount: number
  /** 最后命中时间戳 */
  lastHit: number
  /** 创建时间 */
  createdAt: number
}
```

### 4.2 意图知识库

```typescript
interface IntentKnowledgeBase {
  /** 版本号 */
  version: string
  /** 所有意图条目 */
  intents: IntentEntry[]
  /** 全局配置 */
  config: {
    /** 相似度阈值（低于此值视为无匹配） */
    confidenceThreshold: number
    /** 最大候选意图数 */
    maxCandidates: number
    /** 向量维度 */
    vectorDimension: number
  }
}
```

### 4.3 匹配结果

```typescript
interface IntentMatchResult {
  /** 匹配到的意图 */
  intent: string
  /** 置信度（0-1） */
  confidence: number
  /** 是否需要学习（置信度在灰色地带） */
  needsLearning: boolean
  /** 候选意图列表（用于调试） */
  candidates: Array<{ intent: string; confidence: number }>
}
```

## 5. 意图识别流程

### 5.1 匹配算法

```typescript
async function matchIntent(userInput: string): Promise<IntentMatchResult> {
  // 1. 获取输入文本的嵌入向量
  const inputVector = await aiService.embed(userInput)

  // 2. 与知识库中所有意图的向量计算余弦相似度
  const similarities = knowledgeBase.intents.map(entry => ({
    intent: entry.intent,
    confidence: cosineSimilarity(inputVector, entry.vector),
    hitCount: entry.hitCount
  }))

  // 3. 按置信度排序
  similarities.sort((a, b) => b.confidence - a.confidence)

  // 4. 取最高相似度
  const best = similarities[0]

  // 5. 判断是否命中
  if (best.confidence >= config.confidenceThreshold) {
    return {
      intent: best.intent,
      confidence: best.confidence,
      needsLearning: false,
      candidates: similarities.slice(0, 3)
    }
  }

  // 6. 灰色地带：可能需要学习
  if (best.confidence >= config.confidenceThreshold * 0.8) {
    return {
      intent: best.intent,
      confidence: best.confidence,
      needsLearning: true,  // 标记为需要用户确认
      candidates: similarities.slice(0, 3)
    }
  }

  // 7. 完全无匹配，回退通用对话
  return {
    intent: 'general',
    confidence: 0,
    needsLearning: true,
    candidates: similarities.slice(0, 3)
  }
}
```

### 5.2 余弦相似度计算

```typescript
function cosineSimilarity(a: number[], b: number[]): number {
  let dotProduct = 0
  let normA = 0
  let normB = 0
  for (let i = 0; i < a.length; i++) {
    dotProduct += a[i] * b[i]
    normA += a[i] * a[i]
    normB += b[i] * b[i]
  }
  return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB))
}
```

### 5.3 性能估算

| 步骤 | 预估耗时 | 说明 |
|------|---------|------|
| 文本嵌入 | ~20ms | nomic-embed-text，CPU 推理 |
| 余弦相似度 | <1ms | 纯数学运算（假设 20 个意图） |
| 总延迟 | **~21ms** | 用户完全无感 |

## 6. 学习机制

### 6.1 三种学习方式

#### 方式 A：用户主动纠正（最可靠）

```
用户："帮我查天气"
系统：→ 识别为 "通用对话"（置信度 0.3）

用户纠正："这个应该走主动关怀模块"
系统：→ 记录 "帮我查天气" → "proactive" 存入知识库
系统：→ 重新计算 "主动关怀" 意图的平均向量
```

**触发方式**：在 UI 上提供"这个回答不对，应该是 XX 模块"的反馈按钮。

#### 方式 B：行为隐式学习（最自然）

```
用户："看看这张图"
系统：→ 识别为 "通用对话"
但用户紧接着手动切换到图片分析模块

系统记录：
- 输入："看看这张图"
- 实际使用模块：vision
- 存入知识库，下次自动识别
```

**触发方式**：监听用户手动切换模块的行为，与最近的输入关联。

#### 方式 C：模块执行反馈闭环

```
系统调用模块 → 模块执行成功 → 强化这条映射（hitCount++）
系统调用模块 → 模块执行失败 → 降低置信度权重
```

### 6.2 学习流程

```
用户交互
    │
    ▼
┌─────────────────────────┐
│   识别结果是否正确？      │
└─────┬───────────┬───────┘
      │           │
    正确        不正确
      │           │
      ▼           ▼
  hitCount++    用户纠正
  lastHit=now      │
                   ▼
            ┌──────────────┐
            │ 知识库已有此意图？│
            └──┬────────┬──┘
               │        │
             有        没有
               │        │
               ▼        ▼
          添加示例    创建新意图
          重算向量    初始化向量
               │        │
               └───┬────┘
                   ▼
            持久化到本地文件
```

### 6.3 向量更新策略

当新示例加入某个意图时，需要更新该意图的平均向量：

```typescript
function updateIntentVector(entry: IntentEntry, newExample: string, newVector: number[]): void {
  // 加权平均：旧向量 * 旧权重 + 新向量 * 新权重
  const totalExamples = entry.examples.length + 1
  const oldWeight = entry.examples.length / totalExamples
  const newWeight = 1 / totalExamples

  entry.vector = entry.vector.map((v, i) =>
    v * oldWeight + newVector[i] * newWeight
  )

  entry.examples.push(newExample)
}
```

## 8. 存储设计

### 8.1 文件结构

```
应用数据目录/
  intent/
    knowledge.json          ← 意图知识库（持久化）
    vectors-cache.bin       ← 向量缓存（二进制，加速加载）
    learning-log.json       ← 学习日志（调试用）
```

### 8.2 持久化策略

- **实时保存**：每次学习（用户纠正/隐式学习）后立即写入
- **向量缓存**：启动时加载到内存，避免每次重新计算
- **日志清理**：学习日志保留最近 1000 条，自动清理旧记录

## 附录 A：余弦相似度说明

余弦相似度衡量两个向量的方向相似程度：

```
cos(θ) = (A·B) / (|A|·|B|)
```

- 值为 1：完全相同方向（语义一致）
- 值为 0：正交（无关）
- 值为 -1：完全相反（语义对立）

在实际使用中，文本嵌入的相似度通常在 0.3-0.9 之间，0.75 以上可认为高度相关。
