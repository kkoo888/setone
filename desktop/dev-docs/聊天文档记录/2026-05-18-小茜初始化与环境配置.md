### 任务 4：开发规范同步 ✅

- **参考标准**：[alibaba/p3c](https://github.com/alibaba/p3c)（黄山版）
- **适配文件**：`desktop/CODING_STANDARD.md`（已将 P3C Java 规则映射为 TypeScript 等价规则）

#### 核心规范要点

| 类别 | 规范 |
|------|------|
| 命名 - 类/接口/类型 | PascalCase，不加 `I` 前缀 |
| 命名 - 方法/变量 | camelCase，布尔值以 `is/has/should/can` 开头 |
| 命名 - 常量 | UPPER_SNAKE_CASE |
| 类型安全 | 禁止 `any`，使用 `unknown` |
| 比较 | 使用 `===` / `!==` |
| 空值安全 | 启用 `strictNullChecks` |
| 方法长度 | 单方法 ≤ 80 行 |
| 嵌套深度 | if/for 最多 3 层嵌套 |
| 魔法数字 | 禁止，必须提取为命名常量 |
| 注释 | TSDoc 注释必须 |

## 三、额外完成的工作

### AI 工具调用参数映射修复（核心 Bug）

**问题**：LLM 不知道每个模块工具需要什么参数，导致乱传或不调用工具。

**根因**：`ipc-handlers.ts` 中 `collectModuleTools()` 构建工具定义时，`parameters` 固定为空 schema `{ properties: {} }`。

**影响范围**：14 个模块、69 个工具能力全部受影响。

**修复方案**：
- 新增 `tool-param-schemas.ts`（604 行），创建工具参数 JSON Schema 映射表
- 支持三级回退：模块自定义参数 > 静态映射表 > 空 schema
- 修改 `ipc-handlers.ts`，引入 `getToolParamSchema` 动态查询
- 修改 `capability.ts`，`Capability` 接口新增 `parameters` 字段

### 模块开发规范补充

更新 `dev-docs/模块开发规范.md`，补充工具参数 Schema 章节和完整模块列表。
