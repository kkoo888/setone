## 三、Skill 模块功能规划

### 3.1 初始需求

用户提出三个核心需求：
- **生成新 skill**：创建新的技能模块
- **选择激活 skill**：管理已有技能的启用/禁用
- **炼化创造 skill**：通过使用和迭代优化技能

### 3.2 功能膨胀与精简

助手分析后提出 **22 个功能建议**。用户担心全做会导致冗余，助手随后进行冗余分析，识别出 **4 组重叠功能**：

| 重叠组 | 涉及功能 | 合并结果 |
|--------|----------|----------|
| ① | 在线市场、URL 安装、更新检查 | → **在线安装** |
| ② | 分类标签、收藏夹、搜索过滤 | → **标签 + 搜索** |
| ③ | 安全审查、依赖检查、兼容性校验 | → **安装前自动扫描** |
| ④ | 评分评价（无社区场景）、克隆复制（太简单） | → **移除** |

经过精简，**最终确定 14 个功能**。

## 四、安全方案讨论

### 4.1 用户顾虑

用户担心去掉沙箱执行会不安全。

### 4.2 已有防护分析

助手分析项目已具备 **3 层防护**：
1. `sandbox.ts` — 进程沙箱隔离
2. `capability-arbiter` — 能力权限仲裁
3. 安装前自动扫描 — 安装时安全检查

### 4.3 最终方案

**用"权限声明系统"替代重沙箱**：
- 技能在 `SKILL.md` 中声明所需 `permissions`
- 安装时向用户展示权限需求，由用户确认
- 权限声明**嵌入安装前扫描流程**，不增加额外步骤

**最终确定**：14 个功能 + 权限声明系统（嵌入安装前扫描）

## 七、问题发现与诊断

### 7.1 聊天功能报错

**现象**：用户反馈聊天报错 `"Ollama 请求失败：404"`

**根因**：配置路径不一致
- 设置页面将模型保存到 `appSettings.ollama.model`
- 聊天接口读取 `ollama.model`（默认值 `qwen2.5`）
- 两者路径不同，导致聊天时使用了错误的默认模型配置

### 7.2 Live2D 未显示

**现象**：Live2D 没显示，模块列表也没有

**根因**：组件代码存在但未接入任何页面路由
- `Sidebar` 未引用 Live2D 相关入口
- `MainLayout` 未挂载 Live2D 组件
- 主进程未注册相关 IPC 通道
