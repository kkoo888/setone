## 一、新模块开发流程

### 第一步：读规范

精读 [模块开发规范.md](./模块开发规范.md)，重点关注：

| 章节 | 内容 |
|------|------|
| 第二节 | `module.json` 怎么写 |
| 第三节 | `index.ts` 模板 |
| 第四节 | ESM 模块规范（⚠️ 重要） |
| 第五节 | Checklist（需要改哪些文件） |
| 第九节 | 工具参数 Schema（LLM 调用的关键） |
| 第十二节 | UI/CSS 样式规范 |
| 第十三节 | 前后端对齐规范 |

### 第二步：按 Checklist 逐项创建文件

按规范第五节的清单，依次创建：

**后端**
1. `modules/<id>/module.json`
2. `modules/<id>/index.ts`（实现 activate / deactivate / getCapabilities）
3. `modules/<id>/types.ts`
4. `modules/<id>/services/`
5. `modules/<id>/CHANGELOG.md`
6. `deactivate()` 必须清理所有资源（规范第六节）

**前端**
6. `src/renderer/src/styles/pages/<name>.css`
7. 在 `global.css` 中 `@import` 导入
8. `src/renderer/src/pages/<Name>Page/index.tsx`
9. `src/renderer/src/types/<name>.ts`（如需）

**注册**
10. `Sidebar.tsx` — 添加侧边栏入口
11. `useAppStore.ts` — PanelId 类型添加
12. `MainLayout.tsx` — 添加页面配置
13. `event.ts` — 事件类型（如需跨模块通信）

### 第三步：验证

- [ ] `npm run build` 构建无报错
- [ ] 启动无报错，模块正常激活
- [ ] 模块出现在 ModulesPage
- [ ] 前端 invoke 能调通
- [ ] 禁用/启用正常
- [ ] 侧边栏入口正常显示/隐藏
- [ ] 暗色主题和响应式布局正常
- [ ] AI 对话中工具调用正常（参数传递正确）
- [ ] 热重载后功能正常

### 第四步：提交

```bash
git pull origin dev
git add .
git commit -m "feat: 新增 <模块名> 模块"
git push origin dev
```

## 二、模块重构/修改流程

### 第一步：看文档，搞清楚"应该怎样"

读两份文档：
- `dev-docs/07-模块管理器.md` — 设计意图
- `desktop/dev-docs/模块开发规范.md` — 开发规范

重点搞清楚：生命周期、IPC 注册机制、模块上下文注入了什么

### 第二步：看代码，搞清楚"实际怎样"

| 文件 | 看什么 |
|------|--------|
| `modules/<id>/index.ts` | activate / deactivate / getCapabilities |
| `modules/<id>/module.json` | provides 声明 |
| `src/main/core/module-loader.ts` | activate 流程 |
| `src/main/ipc-handlers.ts` | IPC 注册机制 |

### 第三步：对比，找出不一致

- **A. 文档过时，代码是对的** → 更新文档
- **B. 代码有问题，文档是对的** → 改代码

### 第四步：判断是否真的需要改

三个问题：
1. 这个功能真的用到了吗？
2. 去掉它会不会影响现有功能？
3. 有没有更简单的实现方式？

### 第五步：实施改动

优先级：先改后端 → 再改前端 → 更新 CHANGELOG → 更新文档

### 第六步：验证

```bash
grep -r "旧工具名" modules/<id>/          # 确认旧代码清除
grep -r "invoke(" src/renderer/ | grep "<module>"  # 前后端对齐
npm run build                               # 构建测试
```

### 第七步：提交

```bash
git pull origin dev
git add .
git commit -m "refactor: <模块名> <改了什么、为什么改>"
git push origin dev
```

## 三、注意事项

- **ESM 规范**：项目使用 ESM，禁止 `require`，一律用 `import`（规范第四节）
- **deactivate 清理**：必须清理所有资源，详见规范第六节
- **参数 Schema**：每个 tool 必须有参数定义，详见规范第九节
- **provides/consumes**：即使为空也要写 `[]`，否则会崩溃（规范 12.6）
- **样式**：必须用 CSS 变量、适配暗色主题、用 ModuleHeader（规范第十二节）
